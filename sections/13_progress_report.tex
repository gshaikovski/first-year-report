This chapter presents the first study of this project, which addresses Gap~1 of Section~\ref{sec:bg_gaps} directly and provides preliminary evidence on Gaps~2 and~3.
The study is reported in the paper \emph{Is In-Context Search Worth Its Compute? Two Learning Regimes in Transformers}, prepared for submission to ICLR 2027 with Nathan Herr, Roberta Raileanu, Mateo Espinosa Zarlenga, and Mateja Jamnik; the full paper is attached in Appendix~\ref{app:paper}.

Section~\ref{sec:progress_pilots} reports additional pilot experiments that are not part of the paper.

\section{Motivation}
\label{sec:progress_motivation}

Section~\ref{sec:bg_incontext} ends with a disagreement.
SA reasoning outperforms SO reasoning when both are trained on the same fixed dataset~\citep{lehnertBetterPlanningTransformers2024,gandhiStreamSearchSoS2024}; yet with more data SO models can reach the performance of SA models~\citep{lehnertBetterPlanningTransformers2024}, SO models with test-time scaling can outperform SA models at test-time compute parity~\citep{qinBacktrackNotBacktrack2025}, and traces semantically unrelated to the problem can perform as well as genuine ones~\citep{valmeekamSemanticsUnreasonableEffectiveness2025}.
These results suggest that explicitly learning a search algorithm may be unnecessary or inefficient, but, as Section~\ref{sec:bg_gap_efficiency} argues, none of them can settle the question, because all of them fix the dataset size and none accounts for the training compute that a search trace adds.
The study therefore asks: \emph{how do the relative performance and the compute efficiency of SA and SO reasoning compare across search problems as the available data and model parameters increase?}

\section{Experimental design}
\label{sec:progress_setup}

% TODO: one figure with example SA and SO training sequences for both tasks (from the paper's appendix).
I use two search problems with different structure, representation, and heuristics.
In maze navigation, the state graph is explicit: the grid is listed in the prompt and the edges are implicit pairs of adjacent cells; search traces are generated by A*, following~\citet{lehnertBetterPlanningTransformers2024}.
In Countdown, the graph is implicit: the prompt gives only a list of integers and a target, and every intermediate state must be computed by applying arithmetic operations; search traces are generated by depth-first search, following~\citet{gandhiStreamSearchSoS2024}.
I use a modular variant of Countdown, in which arithmetic is performed modulo a fixed integer, alongside the regular variant, so that the transition structure of the problem can be changed while the encoding, the trace grammar, the model, and the training procedure stay fixed.
GPT-2 transformers~\citep{radfordLanguageModelsAre} of 4 to 12 layers are trained from scratch on SA or SO data, sweeping the dataset size by training on increasing fractions of the full dataset, with each run completing its own learning-rate schedule.
Models are compared on held-out problems at matched training compute, measured in floating-point operations as the product of parameters and tokens processed, and at matched test-time compute, where SO models may sample several candidates and select one with a symbolic verifier, following~\citet{qinBacktrackNotBacktrack2025}.

\section{Results}
\label{sec:progress_results}

\paragraph{Maze navigation is search-optional.}
% TODO: Figure: final_maze_vs_flops (solution error vs training FLOPs, SA vs SO, three depths).
SO models reach the same near-perfect accuracy as SA models with less total training compute, despite requiring marginally more data, and increasing model depth reduces the remaining sample-efficiency gap while preserving the compute advantage of SO models.
Search traces therefore have limited effect on accuracy but a substantial negative effect on training and test-time compute efficiency on this problem.

\paragraph{Modular Countdown is search-efficient.}
% TODO: Figure: final_countdown_error and countdown_pass_at_k_flops.
Only SA models learn the task efficiently: SO models fail to generalise after training on 20 times more unique puzzles, 200 times more seen examples, and a 6 times larger model than the most compute-efficient SA model.
At test-time compute parity, the best SO model with sampling and a verifier reaches 75\% accuracy against near-perfect accuracy for a single SA rollout, and the test-time scaling curves of the 59M- and 344M-parameter SO models overlap, so model size provides little benefit in this regime.
Switching the task from modular to regular arithmetic, with everything else unchanged, makes it efficiently learnable by SO models again.

\paragraph{Two learning regimes, determined by the problem.}
These observations are formalised in the following definition, which is the instrument used throughout Chapter~\ref{ch:proposal}.
\begin{tcolorbox}[title=Definition (Learning regimes), colback=ThesisPurple!5, colframe=ThesisPurple, fonttitle=\bfseries]
For a supervision mode $m \in \{\text{SA}, \text{SO}\}$ and a model size $N$, let $C_m(\epsilon; N)$ be the least training compute, and $D_m(\epsilon; N)$ the smallest number of training samples, with which a size-$N$ model trained under mode $m$ reaches held-out solution error $\epsilon$.
The learning problem is $\epsilon$-\emph{search-optional} if for every model size $N_\epsilon$ at which SA reaches error $\epsilon$ there is a model size $N$ with $C_\text{SO}(\epsilon; N) \le C_\text{SA}(\epsilon; N_\epsilon)$ and $D_\text{SO}(\epsilon; N) \le D_\text{SA}(\epsilon; N_\epsilon)$.
It is $\epsilon$-\emph{search-efficient} if there is a model size $N_\epsilon$ such that every model size $N$ satisfies $C_\text{SO}(\epsilon; N) > C_\text{SA}(\epsilon; N_\epsilon)$ and $D_\text{SO}(\epsilon; N) > D_\text{SA}(\epsilon; N_\epsilon)$.
\end{tcolorbox}
Maze navigation and regular Countdown are search-optional; modular Countdown is search-efficient.
Since varying depth and width does not change the regime while changing the arithmetic does, the regime is determined by the problem's structure rather than by dataset or model size.
Crucially, SA models outperform SO models at small dataset sizes in both regimes, so a comparison at a single dataset size cannot identify the regime; this is why the prior comparisons of Section~\ref{sec:bg_incontext} disagree.

\paragraph{The effect of trace semantics depends on the regime.}
% TODO: Figure: final_trace_types_8l.
Replacing each search trace with a trace from an unrelated problem, following~\citet{valmeekamSemanticsUnreasonableEffectiveness2025}, gives models that perform worse than both SA and SO models on search-optional maze navigation, but better than SO models in sample efficiency on search-efficient modular Countdown, reaching 81\% accuracy with 20M samples while still falling short of SA models.
Trace semantics therefore matter in both regimes, contrary to the prior conclusion, and the sample-efficiency advantage of unrelated traces in the search-efficient regime, which increasing model size alone does not produce, is left unexplained.

\paragraph{Knowing the regime yields a more compute-efficient data mixture.}
% TODO: Figure: final_mixture_error.
Training one model on both tasks with the reasoning mode chosen per task by its regime, SO for maze navigation and SA for modular Countdown, reaches generalisation on both tasks with less training compute than training with SA or with SO reasoning on both.

\section{Additional pilot experiments}
\label{sec:progress_pilots}

% NOTE: unpublished pilots; state seeds/settings if any are reported as numbers.
Three further experiments, not included in the paper, inform the research questions of Chapter~\ref{ch:proposal}.
First, pause and filler tokens~\citep{goyalPauseTokens2024,pfauLetsThinkDot2024} appended to SO data are trivially learnable by the model and produce no effect on either task, so the learning problem collapses into SO reasoning.
Second, models trained with corrupted or unrelated traces on maze navigation learn to ignore the traces once they generalise in-distribution, which likewise collapses to SO reasoning; only on modular Countdown do unrelated traces retain an effect, as reported above.
Third, the best SA model trained on modular Countdown with three numbers, tested on puzzles with four and five numbers, shows a severe drop in performance; the current trace format and setup therefore do not generalise in length, and this result serves as the control baseline for Section~\ref{sec:proposal_rq3}.

\section{Outlook}
\label{sec:progress_outlook}

The study settles that there are search problems on which SA reasoning is the most sample- and compute-efficient method for in-distribution generalisation, that this is not the case for every search problem, and that which case applies is decided by the problem's structure rather than by scale.
It also provides the protocol, matched-compute comparison across data and model sweeps in both regimes, without which the utility of any form of intermediate computation on a search problem cannot be assessed.
For Research Question~1, it leaves open which properties of the structure decide the regime: the evidence rests on two problems and one intervention, and the candidate factors are not isolated.
For Research Question~2, it leaves open what the trace supplies in the search-efficient regime: unrelated traces retain part of the benefit, content-free tokens retain none, and the mechanism is unexplained.
For Research Question~3, it shows only that the current setup does not generalise in length, and everything beyond in-distribution generalisation remains to be done.
Chapter~\ref{ch:proposal} takes up each of these in turn.
